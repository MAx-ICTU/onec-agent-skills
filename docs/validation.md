# Фактические проверки версии 0.1

Ниже сохранён **исторический отчёт исходной версии**, на момент которого запуска в 1С не было. Позднее выполнены Q2–Q4 и ограниченные платформенные проверки: [текущий итоговый отчёт](final-validation.md). [Аудит перед публикацией](publication-review.md) — отдельный промежуточный этап; результаты этих этапов не следует смешивать с первым прогоном.

Дата: 13 октября 2026 года, пользовательская зона Europe/Moscow. Проект создан в пустой рабочей папке (до работы были только `outputs/` и `work/`), действующих `AGENTS.md` в проверенных родительских каталогах не найдено; существующих файлов конфигурации и Git-изменений не было. Исходный приложенный текст не менялся. Публикация и создание удалённого репозитория не выполнялись.

## 1. Структура файлов — выполнено

- Три скилла созданы и проверены поставляемыми `init_skill.py` / `quick_validate.py` из доступного `skill-creator`. Сначала завершён и проверен `onec-refactor`, затем созданы остальные два.
- Для каждого `SKILL.md` внешний валидатор вернул `Skill is valid!`. Он проверяет frontmatter, допустимые поля, имя/описание и незавершённый шаблон; не проверяет BSL или решения агента.
- Собственный `scripts/check_files.py` проверяет читаемость UTF-8, отсутствие BOM, локальные Markdown-ссылки, наличие трёх манифестов, имена и непустые описания. Вызов внешнего валидатора выполняется только при явном параметре пути; для Windows включён UTF-8 в его дочернем Python-процессе.
- Обязательные поля `name`, `description` заполнены, абсолютных зависимостей от машины автора внутри скиллов нет. `onec-query-review` содержит один справочный файл с предметными различающими проверками. Каждый скилл переносится отдельной папкой.

В этой сессии использовались Windows PowerShell, Python **3.12.14**, PyYAML **6.0.3**. PyYAML установлен во временный каталог `work/`, а не глобально. Пользователю для применения инструкций Python не нужен.

Команды для повторения из корня проекта (после установки `requirements-dev.txt`):

```text
python scripts/check_files.py --skill-validator /actual/path/to/skill-creator/scripts/quick_validate.py
python scripts/check_examples.py
```

Путь к валидатору зависит от установки Codex. Наличие только внутренней проверки не следует записывать как выполненный `skill-creator`. Фактический финальный вывод сохранён в [file-checks.txt](file-checks.txt), [model-checks.txt](model-checks.txt).

## 2. Статический анализ и модели — выполнено в ограниченном объёме

Ручной разбор BSL/diff: сохранены экспорт, два округления, серверное размещение, место мутации; в debug отделены логирование и передача ошибки, учтён владелец транзакции; в пакетировании явно ограничены конкурентные изменения и поведение при отказе. Ручной разбор запросов: ключ серии среза, роль реквизита, кардинальность, NULL, гранулярность и законные повторы. Это статический разбор человеком/агентом, **не запуск BSL Language Server, EDT или проверки синтаксиса Конфигуратора**.

`scripts/check_examples.py` выполнил **16 тестов**, все прошли:

| Область | Что проверено | Чего это не доказывает |
| --- | --- | --- |
| Decimal | 5 числовых fixtures, реальные повторы и пустой набор; контрпример двух/одного округления 0.81/0.80 | Семантику точной половины и режима по умолчанию `Окр`, точность реальных метаданных и выполнение BSL |
| Модель потока | Успешная последовательность, продолжение после подавления и отсутствие успеха при повторном выбросе | Реальные транзакции, журнал, отказ фиксации или поведение платформы при ошибке БД |
| Модель среза | Ранний/поздний источник, внешний/внутренний отбор, даты до и на границе | Виртуальную таблицу 1С, активность подчинённых записей, все режимы совместимости |
| SQLite | Размножение суммы, неправильность SUM DISTINCT, неактивное/отсутствующее правое соответствие, корректная группировка | Полный язык запросов 1С, план целевой СУБД, RLS, СКД и агрегат на пустом наборе платформы |
| Python-отображение | Сохранены идентификаторы, порядок, повтор A, отсутствие C и нулевая цена Z; пустой и единичный вход | Выполнение пакетного BSL, конкурентное чтение, сетевую стоимость или ускорение |

Часть проверок — отрицательные контрпримеры намеренно неверных преобразований. Функции модели не читают и не исполняют исходный BSL/`.query`; тесты фиксируют учебную семантику и оракулы. Если изменить код примера, неизменённые модельные тесты сами по себе не докажут корректность нового кода.

Дополнительно в изолированном временном каталоге проверены: копирование трёх папок в документированный `.agents/skills`, сохранение reference, разбор UI-метаданных и отказ проверки файлов при повреждённой ссылке/описании. Результат — [packaging-checks.txt](packaging-checks.txt). Это проверка раскладки и скриптов; обнаружение скиллов запущенным Codex CLI/IDE не тестировалось.

## 3. Фактический запуск в 1С — не был выполнен на этом этапе

`1cv8`/`1cv8c` не найдены в PATH; стандартные каталоги установки в Program Files не обнаружены. Тестовая база, лицензированная платформа, EDT и синтакс-помощник в этой сессии не использовались. Это не инвентаризация всей машины и не утверждение, что 1С нигде не установлена.

Не проверены: компиляция модулей и запросов; запуск `check.bsl`; реальные записи/откаты; роли/RLS; файловый и клиент-серверный режимы; типы клиентов; версии и совместимость; конкуренция; время и планы запросов. Средства проверки и порядок ручного запуска подготовлены в README каждого примера. Номера минимальной/максимальной поддержанной платформы не объявляются.

При адаптации сначала сверить используемые API и директивы с синтакс-помощником **целевой версии**, затем запустить указанные сценарии на тестовой конфигурации. Для Q1 важен независимый периодический регистр с описанными ролями полей. Для Q4 неизменность цен во время операции и уникальность ключа — существенные предпосылки, а не универсальные свойства цены товара.

## 4. Проверка поведения агента — выполнено частично

Проведены **9 учебных заданий**: R1/R2/R3, D1/D2/D3, Q1/Q5/Q6. Сохранены [входы](../evals/inputs.md), [ответы и оценки](../evals/results/README.md). Каждый скилл проверен на проблемном, корректном и неполном входе. После аудита авторская ручная оценка — восемь `pass` и один `partial` (D1: неподтверждённое объяснение защитной проверки транзакции). Это оценка текста решений по учебной рубрике, не исполнения в 1С.

Три оценщика получили отдельный начальный контекст без авторских выводов; три задания внутри каждого скилла шли последовательно в одном контексте. Их модели не переопределялись; точный идентификатор, seed и полная конфигурация не зафиксированы. Скиллы заданы явно, поэтому автоматическое распознавание задачи не проверено. Перед исходной поставкой в `SKILL.md` добавлялись библиографические ссылки без изменения рабочих процессов. Позднее при аудите инструкция debug уточнена; первые девять ответов не являются прогоном этой новой редакции. Это ограниченный smoke-test, не независимая сертификация.

Агент на R1 сохранил оба округления и экспорт; на D1 локализовал подавление и предложил завершение своей транзакции/повторный выброс; на Q1 показал лишнюю строку A и оставил исходный запрос. На корректных входах не предложены обязательные лишние изменения. На неполных входах не выдуманы причины или метаданные. Различия названий, оформления и дополнительная проверка активности транзакции оценивались по смыслу, а не по совпадению эталона.

На момент этого отчёта отдельные прогоны Q2/Q3/Q4 не были выполнены; позднее они сохранены в [query-forward](../evals/query-forward/README.md). Повторных статистических прогонов, независимой экспертной оценки и сравнения с тем же агентом без скилла по-прежнему нет. Нельзя делать вывод о проценте улучшения качества, снижении количества багов или фактической пользе в компании.
