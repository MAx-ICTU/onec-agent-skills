# onec-agent-skills

Три переносимых AI-скилла для разработки и сопровождения решений на **1С:Предприятии**: `onec-refactor` помогает менять структуру BSL с сохранением поведения; `onec-debug` — находить причину сбоя и готовить минимальное исправление; `onec-query-review` — проверять смысл запросов и предложенных оптимизаций. Каждый задаёт агенту предметные решения и проверяемый результат.

Учебная версия **0.1**. Выполнены ограниченные прогоны агента и платформенные проверки в **учебной 1С 8.5.1.1150** на отдельной файловой базе. Промышленное применение, другие версии платформы и улучшение качества относительно обычного промпта не доказаны. Текущие результаты: [итоговый отчёт](docs/final-validation.md); предыдущие этапы: [первичная проверка](docs/validation.md), [аудит](docs/publication-review.md).

## Что входит

| Скилл | Когда использовать | Граница |
| --- | --- | --- |
| [onec-refactor](skills/onec-refactor/SKILL.md) | Трудную процедуру нужно упростить, выделить расчёт, улучшить локальные имена, устранить обоснованное дублирование | Сохраняет поведение, округление, публичный интерфейс, эффекты, транзакции и права. Изменение бизнес-правил оформляется отдельно. |
| [onec-debug](skills/onec-debug/SKILL.md) | Пропадает результат, скрывается исключение, операция зависит от роли или контекста | Начинает с имеющихся свидетельств, различает наблюдение и гипотезу. Без данных не объявляет причину доказанной и не повышает права автоматически. |
| [onec-query-review](skills/onec-query-review/SKILL.md) | Завышены суммы, потеряны строки, предложена оптимизация, запрос выполняется в цикле | Проверяет корректность раньше скорости. Исходного запроса достаточно для начала; второй нужен при сравнении. Возможен результат «замечаний нет». |

Скиллы самостоятельны: можно скопировать любую одну папку из `skills/` **целиком**. У `onec-refactor` и `onec-debug` все инструкции в `SKILL.md`; у `onec-query-review` нужен также `references/query-pitfalls.md`. Общие `docs/`, `examples/`, `evals/` и `scripts/` нужны для изучения и проверки проекта, но не для применения установленного скилла. Дублировать их в папках скиллов не требуется.

Зависимости от других скиллов, конкретной конфигурации, БСП, Python или MCP-сервера нет. Официальные материалы доступны по веб-ссылкам; для проверки API конкретной версии нужен её синтакс-помощник. Это внешние источники, а не вложенные в поставку руководства. `agents/openai.yaml` — необязательная метаинформация Codex; автоматический подбор не отключён.

## Пример до установки: проверка «оптимизации» среза

**Проблема.** В [учебном кейсе Q1](examples/query-review/README.md) отбор по реквизиту `Источник` предложено перенести из `ГДЕ` внутрь `СрезПоследних`. У товара A ранняя ручная цена 10, поздняя импортная — 12; у B только ручная цена 20. Требуются последние цены в целом, оставленные лишь при ручном источнике последней записи. Единственное измерение регистра — `Товар`.

**Действия агента.** В [сохранённом ответе Q1](evals/results/Q1.md) агент проследил выбор последней записи по товару и положение отбора, построил контрпример и предложил оставить исходный запрос.

**Проверяемый результат.** На заданную дату исходный вариант даёт только `(B, 20)`, предложенный — `(A, 10), (B, 20)`: появляется лишняя строка A. В первом ответе это подтверждалось статикой и моделью; позднее обе версии отдельно исполнены на учебной 1С для пяти дат. [Платформенный протокол](evals/platform/README.md) сохраняет эти результаты. Пример показывает отказ от неэквивалентного изменения; измеренного ускорения нет.

## Подключение: Codex CLI или IDE extension

Выбран **локальный каталог скиллов проекта**. Официальная документация проверена 13.10.2026: [Build skills](https://learn.chatgpt.com/docs/build-skills), разделы How ChatGPT and Codex use skills и Where Codex loads local skills. Codex ищет `.agents/skills` от текущего каталога до корня репозитория; в CLI/IDE доступны `$имя` и `/skills`. Если изменения не обнаружены, документация предлагает перезапуск Codex. Это инструкция по документации; интеграционный запуск CLI/IDE в этой поставке не проверялся.

1. Скачайте/распакуйте этот проект. Откройте PowerShell **в его корне**, где находятся `README.md` и `skills/`.
2. Укажите абсолютный путь к своей конфигурации и скопируйте нужные папки в `<ваш-проект>/.agents/skills/`. Пример ниже проверяет наличие всех целевых папок заранее и отказывается перезаписывать их:

```powershell
$ErrorActionPreference = 'Stop'
$bundle = (Resolve-Path -LiteralPath '.').Path
$project = 'C:\dev\my-configuration' # заменить существующим путём
if (-not (Test-Path -LiteralPath $project -PathType Container)) {
    throw 'Каталог проекта не существует'
}
$target = Join-Path $project '.agents/skills'
$names = @('onec-refactor', 'onec-debug', 'onec-query-review')
foreach ($name in $names) {
    if (-not (Test-Path -LiteralPath (Join-Path $bundle "skills/$name/SKILL.md"))) {
        throw "Нет исходного скилла $name"
    }
    if (Test-Path -LiteralPath (Join-Path $target $name)) {
        throw "Скилл $name уже существует; сначала сравните версии"
    }
}
New-Item -ItemType Directory -Path $target -Force | Out-Null
foreach ($name in $names) {
    Copy-Item -LiteralPath (Join-Path $bundle "skills/$name") -Destination $target -Recurse
}
```

3. Запустите Codex CLI/IDE в каталоге конфигурации, проверьте список через `/skills`, выберите скилл через `$` и передайте задачу. Убедитесь по действиям агента, что прочитан нужный `SKILL.md`. Само наличие папки этого не доказывает.
4. Обновление выполняйте осознанным сравнением папок; удаление — удалением только скопированных папок `onec-*` из `.agents/skills`. Эти действия не изменяют исходники конфигурации, но её файлы меняет уже агент в рамках поставленной задачи.

Для одного скилла оставьте только его имя в `$names`. Глобальную установку и магазин плагинов первая версия не настраивает. Для другого AI-инструмента следуйте его документации о локальных skills; одинаковые пути и синтаксис вызова не обещаются. Альтернатива без обнаружения скиллов — явно дать агенту прочитать нужный `SKILL.md` и доступные references, понимая, что это ручное применение инструкций.

## Первое применение

После подключения можно начать так:

```text
$onec-refactor Эту процедуру трудно поддерживать. Выдели расчёт,
сохранив поведение. Код: src/ОбщийМодуль/Module.bsl, процедура Пересчитать.
Изучи доступные вызовы и соглашения проекта. Покажи небольшой diff,
инварианты и фактические проверки. Среды 1С у агента нет.
```

```text
$onec-debug Обработка иногда завершается без результата.
Начни с приложенного модуля и имеющегося сообщения об ошибке.
Ожидается запись результата; вызывающий код считает нормальный возврат успехом.
Раздели свидетельства и гипотезы, предложи следующий различающий шаг,
затем минимальное исправление и способ проверки под исходной ролью.
```

```text
$onec-query-review В этом отчёте завышены суммы. Проверь приложенный запрос.
Требуется одна строка на товар с суммой реальных строк продаж.
Второй версии пока нет. Не выдумывай структуру регистра: уточни только
необходимые ключи и поля. Приведи контрпример, исправление и проверки.
```

Пути в промптах условные; укажите файлы своей конфигурации или вставьте код. В исходниках репозитория нет выдуманных методов вашего проекта. Учебные объекты находятся только в примерах и помечены явно.

## Какие материалы дать и что получить

| Задача | Достаточно для начала | Уточняется по необходимости | Ожидаемый результат |
| --- | --- | --- | --- |
| Рефакторинг | Фрагмент и цель «сохранить поведение», доступ к правилам проекта | Вид модуля, связанные вызовы/метаданные событий, точность данных и значимые эффекты | Локальный patch, решения и проверка результатов/эффектов до и после |
| Отладка | Симптом, ожидаемое поведение, доступный код или сообщение | Следующее влияющее свидетельство: стек, вход, роль, участок журнала, условия повтора | Причина с доказательствами либо честный промежуточный диагноз; минимальное исправление и повторная проверка |
| Запросы | Исходный текст, желательно цель результата | Роль полей и ключи, параметры, кратность, контрольные строки; кандидат — только для сравнения | Доказанные проблемы отдельно от рисков, контрпример, исправленный/сохранённый запрос и процедура проверки |

Платформу, режим совместимости, тип клиента и файловую/серверную среду укажите сразу, если знаете. Они обязательны для проверки зависящих от них решений, но не мешают начать статический разбор. При использовании БСП сообщите её точную версию и предоставьте соответствующий API, если он нужен задаче.

Результат без 1С — подготовленное изменение и статическое обоснование с процедурой проверки. Синтаксический анализ, запуск на тестовой базе и воспроизведение инцидента — разные уровни подтверждения.

## Практические ситуации

- **Сопровождение:** старый модуль нужно сделать понятнее перед следующей задачей. `onec-refactor` сохраняет публичную точку и порядок действий, не превращая разбор в массовое переименование.
- **Поиск ошибки:** в журнале есть исключение, а пользователю приходит успех. `onec-debug` проверяет продолжение после обработчика и владельца транзакции, затем исправляет ошибочный путь.
- **Ревью отчёта:** продажи соединены с несколькими метками товара. `onec-query-review` проверяет кратность до суммирования и сохраняет реальные повторные продажи.
- **Ревью оптимизации:** отбор перенесён внутрь среза либо несколько запросов заменены одним. Скилл сначала проверяет выбранные записи, исходные строки, повторы и временную семантику чтения; ускорение подтверждается отдельно.

Польза относительно обычного обращения к агенту — **проектная цель**: не забывать предметные инварианты, строить контрпримеры и передавать воспроизводимую проверку. Сравнительного исследования «со скиллом / без скилла» нет; проценты улучшения и ускорения не заявляются.

## Проверки проекта

Для применения скиллов установка зависимостей не нужна. Для воспроизведения проверок — Python 3.10+ и PyYAML:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe scripts/check_files.py
.venv\Scripts\python.exe scripts/check_examples.py
```

Если в вашем Codex доступен `skill-creator`, найдите поставляемый с ним `scripts/quick_validate.py` и передайте **его реальный путь**:

```powershell
.venv\Scripts\python.exe scripts/check_files.py --skill-validator 'C:\path\to\skill-creator\scripts\quick_validate.py'
```

`check_files.py` проверяет YAML, имена, комплектность и локальные Markdown-ссылки, включая выход ссылок и UI-ресурсов за пределы каждой папки скилла; при указанном пути дополнительно вызывает валидатор `skill-creator`. Без этого параметра он не утверждает, что внешний валидатор выполнен. `check_examples.py` проверяет учебные модели Decimal/SQLite/Python, включая отрицательные контрпримеры неверных исправлений. Эти проверки не исполняют BSL и язык запросов 1С. Проверка переноса отдельных папок и отрицательные проверки упаковки: `python scripts/check_packaging.py`.

Текущий статус, ответы Q2–Q4 и команды — в [итоговом отчёте](docs/final-validation.md). Существующие `check.bsl` рефакторинга и отладки выполнены на учебной 1С 8.5.1.1150; [платформенный протокол](evals/platform/README.md) описывает точный объём. При дополнительной проверке исправлена потеря строковых соответствий в учебном Q4; неудачный результат сохранён. Скилл не заменяет ревью разработчика, синтакс-помощник целевой платформы и проверку на данных конкретной конфигурации. RLS, СКД, конкуренция, производительность и обнаружение скиллов в CLI/IDE не проверены.

## Развитие и публикация

Полезное следующее изменение приносит новый исходный пример, наблюдаемый сбой решения и критерий успешного поведения; одной новой общей рекомендации недостаточно. При изменении скилла повторите затронутые сценарии и сохраните фактический ответ агента, инструмент/модель, контекст и выполненные проверки. Не публикуйте рабочие журналы и данные клиентов как fixtures.
