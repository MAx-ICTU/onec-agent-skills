# Проверка запросов 1С

Проверь соответствие результата задаче, затем оцени производительность. Уже корректный запрос может не требовать изменений. Не создавай замечания ради количества.

## Вход и контракт результата

Начни с предоставленного текста запроса и инструкций проекта. Изменённый вариант нужен только для сравнения версий. По мере анализа уточни необходимые поля метаданных: типы, измерения, ресурсы и реквизиты регистра; периодичность и подчинение регистратору; ключи и кардинальности соединений; параметры, права и ожидаемую гранулярность результата (что означает одна строка).

Не требуй всю конфигурацию для каждого ревью. Если семантика зависит от неизвестного поля, дай условный вывод и один различающий вопрос, не придумывая его роль. Версию платформы, режим совместимости, СУБД, тип клиента и среду уточняй, если они влияют на конкретное средство или измерение. СКД, динамические списки и программные доработки могут изменять исполняемый текст: при соответствующем симптоме изучи итоговый запрос и настройки.

## Проверка корректности

Проследи гранулярность, ключ и количество строк на каждом шаге: исходные данные → виртуальные/временные таблицы → соединения → отбор → группировка → итог. Сначала ищи минимальный набор данных, на котором требуемый результат расходится с фактическим или предложенной версией.

При затронутом механизме прочитай соответствующий пункт [references/query-pitfalls.md](references/query-pitfalls.md):

- Для `СрезПоследних` различай отбор записей до построения среза и отбор результата среза; положение отбора по реквизиту/ресурсу может менять смысл. Не применяй правило «всегда переносить в параметры».
- Для соединений докажи кардинальность по полному ключу. Несколько строк справа могут размножить каждую строку слева. `РАЗЛИЧНЫЕ` и `СУММА(РАЗЛИЧНЫЕ ...)` не являются общим исправлением: они могут уничтожить законные повторы.
- Для левого соединения проверь `NULL` и место условия на правую сторону. Потеря строк без соответствия — ошибка только относительно требуемого результата. Пустая ссылка, `Неопределено` и `NULL` не взаимозаменяемы.
- Для запроса в цикле сохрани исходный идентификатор строки, её порядок при необходимости, повторы, отсутствующие соответствия и **полный набор параметров** каждой итерации. `В (&Список)` возвращает множество подходящих данных, а не автоматически один результат на каждый исходный элемент. Проверь, допустимо ли единое чтение вместо чтений в разные моменты; не пакетируй через границы значимых записей/транзакций.

Отделяй доказанное расхождение, условный риск и отсутствие проблемы. Если нет метаданных или данных для доказательства, не выдавай возможное размножение за установленный факт.

## Изменение и проверка

Предложи минимальный исправленный запрос или оставь исходный с объяснением. Явно укажи цель: эквивалентность прежней версии или исправление ошибочного результата. Не доказывай исправление сравнением с заведомо ошибочной старой суммой.

Сравни состав строк, ключи, кратность, `NULL`, значения и агрегаты; порядок — только если он задан контрактом и `УПОРЯДОЧИТЬ ПО`. Добавь наборы с нулём, одним и несколькими соответствиями, законными повторами, границами периода/среза. Для пакетирования сверяй результат **по исходной строке**, а не только общий итог. Не заменяй механизм среза обычным SQL в проверке без явного ограничения модели.

Только после этого оцени стоимость: число обращений, объём промежуточных данных, индексы и план на целевой СУБД. Ускорение без сравнимых измерений обозначь ожидаемым эффектом. Для замеров зафиксируй версию/совместимость, СУБД, параметры, объём данных, роль, одинаковые условия кеша и повторные прогоны. Не обещай процент ускорения по виду текста.

Без доступа к 1С выполни доступный статический разбор, приведи контрпример/модель и процедуру проверки на тестовой базе. Не утверждай компиляцию запроса, эквивалентность для всех данных или фактическое ускорение.

Отчёт: контракт; доказанные проблемы с примером; гипотезы и необходимые сведения; исправление либо аргументированное отсутствие изменений; фактические проверки; невыполненные проверки и способ измерения.

## Основания и границы

- [Developer Guide 8.3.27, §§8.4.9.2.2–8.4.9.2.3](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/#8-4-9-query-source-description): комбинации строк внутреннего соединения и строки с `NULL` при левом внешнем соединении. Примеры скилла — самостоятельные выводы, не копии примеров руководства.
- [Using filters in queries with virtual tables, пример SliceLast](https://1c-dn.com/library/using_filters_in_queries_with_virtual_tables/): официальный материал различает положение отбора и роль полей регистра. Его рекомендация передавать больше отборов в параметры ограничена следующим в статье разбором изменения смысла среза; это не требование переносить любой отбор. На странице не закреплена версия и есть опечатка первого запроса среза; не копируй его механически.
- [Query language, Using the ISNULL() function / Specifics of connecting to the virtual balances table](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Queries/Query_language/?language=en): официальные пояснения `NULL` при отсутствии соответствия.
- Проверка кратности, контрпримеры и отображение пакетных результатов на исходные строки — инженерные приёмы этого скилла. Доступность синтаксиса и особенности виртуальных таблиц сверяй с документацией и синтакс-помощником применимой версии; зависимости от БСП нет.
