# Платформенные проверки 13.10.2026

Выполнено на **учебной 1С:Предприятие 8.5.1.1150**, совместимость `Version8_5_1`, новая файловая база с синтетическими метаданными и данными. Режим исполнения — управляемый толстый клиент `1cv8t.exe`; серверные общие модули. Настроенных пользователей/ролей нет, чтение разрешено. Серверный и тонкий клиентский синтаксис проверены конфигуратором, но отдельного исполнения тонкого клиента не было. [Параметры среды](environment.json).

Ранее поиск только PATH и каталогов `1cv8` не находил платформу. Дополнительный поиск установленного продукта обнаружил учебную редакцию `1cv8t`. Это исправляет прежний вывод об отсутствии доступной среды; исторические отчёты помечены как предыдущие этапы.

База не добавлялась в пользовательский список (`/AddToList` отсутствует). Существующие базы не открывались. Для кеша платформы потребовался разрешённый запуск вне файлового sandbox; первый отказ записи кеша сохранён в журналах. Запуск был скрытым. Каждый процесс имел таймаут 45 секунд; итоговые стадии завершились до таймаута. Экземпляры базы, кеш и `1Cv8.1CD` в поставку не включены.

## Найденная ошибка и повтор

В [старом after.bsl](q4-failure/after.bsl) цены выбирались по множеству товаров, затем искались в `Соответствие` по строковому ключу. Запрос находил `A` для `a` и `A `, а обратный поиск не находил ключ. [Неудачный журнал](q4-failure/results.txt) и [ошибка](q4-failure/client-error.txt): ожидалась цена 10 с Истина, получены 0 с Ложь. Первоначальный агент Q4 уже использовал числовые ID и на этом наборе прошёл.

Текущее исправление: таблица исходных строк помещается во временную таблицу; соответствие товаров определяется левым соединением, результат возвращается по числовому ID. Сохранены сигнатура, порядок и все строки. В справочник добавлены [официальные правила сравнения, §8.4.18.3](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/#8-4-18-conditions-in-query-language); выбор numeric ID — собственное инженерное решение. Платформа подтвердила конкретные `a`/`A `, но не все возможные collations.

После уточнения reference проведён [независимый повтор Q4](../query-forward/README.md). На новой итоговой базе и первоначальный агент, и повтор, и исправленный пример прошли весь набор, включая выявленный контрпример. Сохранены [baseline](logs/results-baseline.txt), провал и итог, а не только успешный журнал.

При подготовке стенда были ошибки XML метаданных и служебного BSL (свойство документа, уникальность UUID, область переменной, зарезервированное имя). Они исправлены до фактических утверждений; соответствующие load/syntax-журналы не удалены. Это ошибки тестового стенда, не ответы оцениваемых агентов. `client-error.txt` прежнего провала не считается текущим результатом.

## Повторение

[Исходники конфигурации](source/Configuration.xml) и серверный [стенд](source/CommonModules/ПлатформенныеПроверки/Ext/Module.bsl) сохранены. В локальных путях стоят `{{RUN_ROOT}}` и `{{PROJECT_ROOT}}`. Они заменяются подготовщиком; код процедур агентов не переписывается. [prepare.py](prepare.py) создаёт **новый** каталог с source, входами и местом для базы. Его запуск не запускает 1С:

```powershell
python evals/platform/prepare.py 'C:\temp\onec-validation-new'
```

Затем в отдельном терминале укажите свой путь к 1С и новый подготовленный каталог. Не добавляйте рабочую базу и не меняйте режим совместимости без нового анализа. Порядок действий соответствует реально выполненным стадиям:

```powershell
$exe = 'C:\Program Files (x86)\1cv8t\8.5.1.1150\bin\1cv8t.exe'
$run = 'C:\temp\onec-validation-new'
& $exe CREATEINFOBASE "File=`"$run/base`";" /Out "$run/platform/create.log" /L ru /DisableStartupDialogs /DisableStartupMessages /DisableSplash
& $exe DESIGNER /F "$run/base" /LoadConfigFromFiles "$run/config" /UpdateDBCfg /Out "$run/platform/load.log" /L ru /DisableStartupDialogs /DisableStartupMessages /DisableSplash
& $exe DESIGNER /F "$run/base" /CheckConfig -Server -ThinClient /Out "$run/platform/syntax.log" /L ru /DisableStartupDialogs /DisableStartupMessages /DisableSplash
& $exe ENTERPRISE /F "$run/base" /Out "$run/platform/enterprise.log" /L ru /DisableStartupDialogs /DisableStartupMessages /DisableSplash
Get-Content "$run/platform/results.txt"
```

Дождитесь завершения каждой стадии; не объединяйте загрузку с `/CheckConfig`, поскольку порядок операций может проверять старую редакцию модулей. Оценивайте и журналы, и завершающий маркер, а не только exit code. Повторный запуск runtime на той же базе не предусмотрен: стенд создаёт записи заново; для повтора подготовьте новый каталог.

Синтаксис команд сверялся с официальным [Designer batch mode](https://1c-dn.com/1c_enterprise/designer_batch_mode/) и [режимом создания базы](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.24_Administrator_Guide/Appendix_7._The_parameters_of_the_command_line_to_launch_1C_Enterprise/7.2._Selecting_run_mode/7.2.3._Launch_in_the_infobase_creation_mode/?language=en). Фактические команды, времена, exit codes — `logs/*-process.json`. При экспорте заменены абсолютные пути и нормализованы UTF-8/переводы строк; [raw-evidence-hashes.json](raw-evidence-hashes.json) хранит хеши исходных локальных файлов. Исходники стенда — синтетические; никаких данных рабочих баз нет.

Успех ограничен этой учебной версией, совместимостью и файловым режимом. Промышленная СУБД, другие клиенты/версии, роли/RLS, СКД, БСП, реальные записи/откат, конкуренция, нагрузка, план и ускорение остаются **невыполненными проверками**. Это позволяет завершить учебную поставку, но не подтверждает промышленную пригодность.
