# R1 — выделение расчёта с сохранением поведения

Применён `onec-refactor/SKILL.md`. Прочитаны только заданный SKILL.md и `examples/refactor/before.bsl`. Проект не изменён; ниже предлагаемая замена содержимого модуля и patch. Базы, раннера и синтакс-помощника 1С нет.

## Предлагаемый код

```bsl
// Самостоятельный учебный пример. Серверный общий модуль, без БСП и метаданных.
Процедура ПересчитатьТовары(Товары) Экспорт

    Для Каждого СтрокаТовара Из Товары Цикл
        СтрокаТовара.Сумма = РассчитатьСуммуТовара(
            СтрокаТовара.Количество,
            СтрокаТовара.Цена,
            СтрокаТовара.СкидкаПроцент);
    КонецЦикла;

КонецПроцедуры

Функция РассчитатьСуммуТовара(Количество, Цена, СкидкаПроцент)

    СуммаДоСкидки = Окр(Количество * Цена, 2);
    СуммаПослеСкидки = Окр(СуммаДоСкидки
        * (100 - СкидкаПроцент) / 100, 2);

    Возврат СуммаПослеСкидки;

КонецФункции
```

## Решения и инварианты

- Экспортная процедура `ПересчитатьТовары(Товары)` сохранена с прежними именем, параметром и передачей по ссылке. Внешнему коду менять вызов не требуется. Другие вызывающие места по условию не читались, поэтому публичный интерфейс не переименовывается.
- Неглобальный серверный общий модуль и его свойства остаются прежними: Сервер включён, Вызов сервера и Привилегированный выключены. Новая функция находится в том же модуле, без `Экспорт`; вызов внутренний, из серверной процедуры. Переноса на клиент или дополнительного удалённого вызова нет. Директивы формы не добавлены.
- Расчёт получает три явных числовых входа, возвращает число и не присваивает входным параметрам. `Знач` не добавлено: расчёт не изменяет аргументы. Объект таблицы в расчёт не передаётся.
- Обе исходные операции `Окр(..., 2)` сохранены в прежнем порядке, с тем же отсутствующим третьим аргументом. Сначала округляется произведение количества и цены, затем рассчитанная с этого округлённого числа сумма со скидкой. Режим округления не предположен и не заменён.
- Порядок умножения и деления и промежуточные переменные сохранены. Колонки по контракту числовые, без ограничений точности; новых преобразований типов, точности или ограничений колонок нет.
- Единственная мутация — запись суммы текущей строки после успешного расчёта. Обход таблицы остаётся последовательным. Не добавлены итоговое округление, копирование таблицы, предварительный расчёт всех строк, запись объектов, сообщения, обработка ошибок, транзакции и проверки прав.
- Ноль и отрицательное количество проходят ту же формулу. Не добавлены запреты отрицательных значений, ограничения скидки диапазоном 0–100 или новые значения по умолчанию.
- При арифметическом исключении уже завершённые строки остаются пересчитанными, текущая строка ещё не получает новую сумму, следующие не обрабатываются. Исключение продолжает распространяться. Стек/строка диагностики изменятся из-за выделения функции; побайтовое совпадение текста диагностики не обещается.

При вызове функции все три свойства читаются до арифметики; в исходнике скидка читалась после первого округления. Для заданной обычной `ТаблицаЗначений` с существующими числовыми колонками чтение скидки само по себе не имеет побочных эффектов и не меняет данные. Поэтому это различие не влияет на контракт. Эквивалентность не распространяется на произвольный объект с иными свойствами или отсутствующей колонкой: такой вход исключён постановкой.

## Фактически выполненная проверка

Статически сопоставлены исходный код и предлагаемая замена. Дополнительно PowerShell проверил текстовые признаки: исходную экспортную сигнатуру, два вызова `Окр`, сохранение цикла, единственную запись в колонку суммы, отсутствие экспорта новой функции и отсутствие добавленной обработки ошибок/транзакций/привилегированного режима. Все шесть проверок прошли.

Это текстовые проверки, не BSL-анализатор и не доказательство выполнения на платформе. Сопоставление формул выполнено вручную: подстановка `Количество = СтрокаТовара.Количество`, `Цена = СтрокаТовара.Цена`, `СкидкаПроцент = СтрокаТовара.СкидкаПроцент` даёт исходные выражения без перестановки операций. Проверено вручную, что функция не присваивает параметрам, а процедура сохраняет место мутации строки. Математический эмулятор не запускался: он не подтвердил бы фактическую семантику `Окр` платформы.

## Проверки на целевой платформе — подготовлены, не выполнены

1. В отдельной тестовой конфигурации создать неглобальный серверный общий модуль с указанными свойствами. Сохранить исходную процедуру под временным именем `ПересчитатьТоварыДо`, рядом разместить предложенную процедуру и функцию. Проверить модуль средствами целевой версии платформы. Продуктивный экспорт при этом не переименовывать: временное имя нужно только для стенда.
2. Из серверного тестового кода создать `ТаблицаЗначений` с четырьмя колонками типа Число без ограничения точности. Для каждой проверки сделать две независимые копии таблицы: одну обработать исходной процедурой, вторую новой. Перед вызовами заполнить `Сумма` контрольными значениями, чтобы видеть факт изменения. Сравнить число/порядок строк и значения всех четырёх колонок; изменяться должна только `Сумма`.
