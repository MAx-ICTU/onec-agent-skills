# Q1 — эквивалентность оптимизации СрезПоследних

Вердикт: предложенная оптимизация неэквивалентна исходному запросу и нарушает заданный контракт. Исходный запрос следует оставить.

## Контракт и метаданные

На дату `03.01.2026 00:00:00` требуется сначала получить последнюю цену каждого товара среди всех источников, затем оставить только товары, у которых источник этой последней записи — `ручной`. Гранулярность: одна строка на товар; выводятся `Товар`, `Цена`. Порядок строк не задан.

Регистр `УчебныеЦены` независимый, периодический (секунда), не подчинён регистратору. Единственное измерение — `Товар` (Строка20); `Источник` (Строка20) является реквизитом, `Цена` (Число15,2) — ресурсом. Поэтому серии записей определяет товар, источник не является частью ключа серии.

## Доказанное расхождение

Исходные данные:

| Период | Товар | Источник | Цена |
|---|---|---|---:|
| 01.01.2026 00:00:00 | A | ручной | 10 |
| 02.01.2026 00:00:00 | A | импорт | 12 |
| 01.01.2026 00:00:00 | B | ручной | 20 |

В исходном запросе `СрезПоследних(&Дата)` выбирает `A / импорт / 12` и `B / ручной / 20`. Последующий `ГДЕ Цены.Источник = &Источник` исключает A. Результат: единственная строка `(B, 20)`.

В предложенном запросе параметр виртуальной таблицы `Источник = &Источник` исключает импортную запись до построения среза. Последними среди ручных становятся `A / ручной / 10` и `B / ручной / 20`. Результат: `(A, 10)`, `(B, 20)`.

Таким образом, меняются состав ключей и количество строк (1 → 2). Цена A=10 относится к более ранней записи и не соответствует последней цене товара в целом. Уже две записи одного A — ранняя ручная и поздняя импортная — составляют минимальный контрпример; B служит контролем корректного включения. Проблема доказана для предоставленных метаданных; это не гипотеза о производительности.

## Решение

Цель — сохранить контракт и семантику исходной версии. Минимальное решение — оставить исходный запрос без изменений:

```bsl
ВЫБРАТЬ
    Цены.Товар,
    Цены.Цена
ИЗ
    РегистрСведений.УчебныеЦены.СрезПоследних(&Дата) КАК Цены
ГДЕ
    Цены.Источник = &Источник
```

Для данного вывода дополнительных метаданных не требуется. Переносить этот контрпример на регистр, где Источник является измерением, нельзя без повторного анализа ключа серии.

## Фактически выполненные проверки

Прочитаны только SKILL.md данного скилла, его references/query-pitfalls.md и два заданных запроса. Выполнен статический разбор места отбора и ключа серии. В PowerShell исполнена модель: допустимые по дате записи → при необходимости предварительный отбор источника → последняя запись по каждому товару → итоговый отбор. Все пять проверок модели прошли:

| Дата | Исходный: ожидаемо и получено моделью | Предложенный: ожидаемо и получено моделью |
|---|---|---|
| 31.12.2025 23:59:59 | пусто | пусто |
| 01.01.2026 00:00:00 | A=10; B=20 | A=10; B=20 |
| 01.01.2026 23:59:59 | A=10; B=20 | A=10; B=20 |
| 02.01.2026 00:00:00 | B=20 | A=10; B=20 |
| 03.01.2026 00:00:00 | B=20 | A=10; B=20 |

Эти случаи покрывают отсутствие допустимых записей, включение записи ровно на границе секунды, состояние перед сменой источника, одну запись в серии B и несколько записей в серии A. Товар без записей не появляется ни в одном результате. Соединений, агрегатов и восстановленных отсутствующих соответствий в запросах нет; NULL и размножение строк соединением здесь неприменимы. Повторы одного товара в разные периоды учитываются как история серии, а не как несколько выходных строк.

## Границы и проверки на тестовой базе

Модель явно ограничена указанным независимым регистром с одним измерением, уникальными периодами внутри каждой серии и сравнением `Период <= Дата`. Это иллюстрация семантического расхождения, а не исполнение виртуальной таблицы 1С и не доказательство эквивалентности на всех данных. Обычный SQL вместо механизма среза не использовался. Доступа к 1С нет: компиляция запросов, реальные результаты платформы и время исполнения не проверены.

Для проверки на 1С создать тестовый регистр с заданной структурой, записать три строки, задать параметры Дата (Дата) и Источник (Строка), выполнить обе версии для пяти дат таблицы и сравнить состав ключей, кратность и цены без требования порядка. Дополнительно проверить пустой регистр и товар с единственной импортной записью: обе версии должны вернуть пустой результат для такого товара. Зафиксировать версию платформы и режим совместимости, если фактическое поведение отличается от модели.

Фактическое ускорение не установлено. Сравнивать скорость неэквивалентной версии как улучшения нельзя. Для дальнейших корректных кандидатов измерять на целевой СУБД при одинаковых параметрах, объёме данных, роли и условиях кеша; фиксировать версию/совместимость, план, объём промежуточных данных и повторные прогоны. Процент ускорения по тексту запросов не заявляется.
