# Q5 — проверка correct.query

Вывод: запрос соответствует заданному контракту. Доказанных проблем нет; изменения не требуются. Оснований обещать ускорение по предоставленным сведениям нет.

## Контракт и анализ

Требуется сумма всех реальных строк табличной части `Документ.УчебнаяПродажа.Товары` выбранного документа по товару. Исходная гранулярность — строка документа с ключом `Ссылка, НомерСтроки`. После отбора `Продажи.Ссылка = &Документ` остаются строки только заданного документа. Группировка по `Товар` создаёт одну строку на товар; `СУММА(Продажи.Сумма)` учитывает каждую реальную строку ровно один раз.

`Товар` — Строка20, `Сумма` — Число15,2, параметр `Документ` — ссылка на заданный документ. Соединений нет, поэтому источник размножения строк отсутствует. Порядок результата контрактом не задан и в запросе не установлен; это не ошибка.

## Проверка данных

Для одного документа заданы строки `(1,A,100)`, `(2,A,100)`, `(3,B,50)`. Две строки A имеют разные номера строк и являются законными отдельными продажами, даже при одинаковых товаре и сумме.

| Товар | Слагаемые | Результат |
|---|---|---:|
| A | 100 + 100 | 200 |
| B | 50 | 50 |

Добавление `РАЗЛИЧНЫЕ` к исходным данным с потерей номера строки или применение `СУММА(РАЗЛИЧНЫЕ Продажи.Сумма)` здесь могло бы потерять законный повтор и дать A=100. Такого исправления запросу не требуется. Контрольный общий итог — 250; он согласуется с суммой всех трёх исходных строк.

## Решение

Оставить исходный запрос без изменений:

```bsl
ВЫБРАТЬ
    Продажи.Товар,
    СУММА(Продажи.Сумма) КАК Сумма
ИЗ
    Документ.УчебнаяПродажа.Товары КАК Продажи
ГДЕ
    Продажи.Ссылка = &Документ
СГРУППИРОВАТЬ ПО
    Продажи.Товар
```

Цель — сохранить корректный результат. Данных для условных замечаний о ключах, NULL либо соединениях нет, и такие замечания не вводятся.

## Фактически выполненные проверки и границы

Использованы ранее прочитанный SKILL.md и текст correct.query. README и fixtures не читались. Выполнен статический разбор отбора, ключей, кратности и агрегации. Исполнена модель PowerShell с тремя указанными строками: получены и проверены A=200 и B=50. Дополнительная проверка модели с выбором отсутствующего документа дала ноль групп. Модель проверяет простое суммирование строк; это не исполнение запроса 1С.

1С недоступна: компиляция запроса и результаты на реальной платформе не проверены. На тестовой базе следует выполнить запрос с заданными тремя строками и сверить пары `(A,200)`, `(B,50)` без сравнения порядка; также проверить пустую табличную часть (ноль строк), единственную строку (её сумма), несколько строк одного товара, нулевую сумму и строки другого документа (они не должны попасть в результат). Права чтения должны соответствовать контракту получения всех строк выбранного документа.

Для заключения о производительности нужны фактический план и повторные замеры на целевой базе с зафиксированными версией/совместимостью платформы, СУБД, объёмом данных, параметром, ролью и условиями кеша. Индексы и ускорение без этих сведений не объявляются установленными; текущая форма запроса сама по себе не показывает необходимость оптимизации.
