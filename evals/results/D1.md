# D1: ложный успех после сбоя шага

## Симптом и контракт

Ожидается: успешный возврат только после выполнения шага и фиксации собственной транзакции. При сбое вызывающий код должен получить исключение.

Наблюдаемый симптом: иногда normal return воспринимается как успех, хотя шаг не выполнен. Предоставлен конкретный вход `ИмитироватьСбой = Истина`. Частота этого входа в рабочей базе неизвестна.

Контекст задан: серверный неглобальный общий модуль; Сервер включён, Вызов сервера и Привилегированный выключены. Вызов производится с сервера вне активной транзакции. `Трасса` — изменяемый массив строк. Запись журнала в учебной среде разрешена и не выбрасывает исключений. Платформа 1С недоступна.

## Свидетельства и причинная цепочка

Прочитаны только указанные `skills/onec-debug/SKILL.md` и `examples/debug/before.bsl`.

1. `ВыполнитьОперацию` начинает собственную транзакцию.
2. При `ИмитироватьСбой = Истина` процедура `ВыполнитьШаг` выбрасывает `Учебный сбой шага` до добавления строки `Шаг`.
3. Обработчик `Исключение` записывает описание ошибки в журнал, но не отменяет транзакцию и не передаёт исключение вызывающему коду.
4. После обработчика управление переходит к `ЗафиксироватьТранзакцию()` и `Трасса.Добавить("Успех")`.
5. Если фиксация и добавление в массив завершаются нормально, процедура возвращает управление без исключения. При изначально пустой трассе результат — `["Успех"]`, без `"Шаг"`.

Подтверждённая статически причина для этого пути — подавление исключения с последующим выполнением общего завершения успехом. Журналирование само по себе не меняет результат вызова. «Иногда» объясняется различием входа для данного примера, но частота и причина реального производственного инцидента этим не установлены.

Гипотезы о гонке, RLS, неверных правах или клиентском контексте для доказанного пути не нужны: ветка определяется входным флагом, а доступность журнала задана контрактом. Они не проверялись в рабочей базе.

## Предлагаемый BSL

```bsl
Процедура ВыполнитьОперацию(Знач ИмитироватьСбой, Трасса) Экспорт

    НачатьТранзакцию();
    Попытка
        ВыполнитьШаг(ИмитироватьСбой, Трасса);
        ЗафиксироватьТранзакцию();
    Исключение
        Если ТранзакцияАктивна() Тогда
            ОтменитьТранзакцию();
        КонецЕсли;
        ЗаписьЖурналаРегистрации("onec-agent-skills.УчебнаяОперация",
            УровеньЖурналаРегистрации.Ошибка, , , ОписаниеОшибки());
        ВызватьИсключение;
    КонецПопытки;
    Трасса.Добавить("Успех");

КонецПроцедуры

Процедура ВыполнитьШаг(Знач ИмитироватьСбой, Трасса)

    Если ИмитироватьСбой Тогда
        ВызватьИсключение "Учебный сбой шага";
    КонецЕсли;
    Трасса.Добавить("Шаг");

КонецПроцедуры
```

Изменение локально: отмена собственной активной транзакции и повторный выброс исходного исключения исключают ложный успех. Фиксация перенесена в `Попытка`, чтобы её отказ также проходил через обработчик завершения транзакции. Проверка активности нужна потому, что к моменту обработки ошибки фиксации транзакция уже может быть завершена платформой. Журналирование остаётся после отмены; по контракту оно не маскирует исходную ошибку. `НачатьТранзакцию()` остаётся перед `Попытка`: если начало не удалось, ошибка сразу передаётся вызывающему коду.

## Фактические проверки

Выполнен статический разбор обеих веток исходника и предложенного изменения. Код проекта не редактировался. Компиляция BSL, запуск в 1С, просмотр реального журнала и проверка состояния транзакции в платформе не выполнялись.

| Сценарий с новым пустым массивом | Исходник, если остальные операции успешны | Предлагаемый код, если отмена и журналирование успешны |
|---|---|---|
| `Ложь` | normal return; `Шаг`, `Успех`; фиксация | То же |
| `Истина` | normal return; только `Успех`; запись ошибки; фиксация | Исключение `Учебный сбой шага`; пустая трасса; отмена; запись ошибки |
| Ошибка фиксации | Исключение выходит за пределами обработчика; завершение транзакции не обеспечено кодом | Обработчик отменяет оставшуюся активной транзакцию, журналирует и повторно выбрасывает исключение |

После повторного выброса строка `Успех` недостижима на обработанной ветке ошибки. Вызов вне активной транзакции даёт процедуре право отменять начатую ею транзакцию. Привилегированный режим и права менять не требуется.

## Воспроизводимая проверка в 1С

В учебной базе разместить предложенный код в серверном неглобальном общем модуле с указанными свойствами. Выполнить следующие вызовы из серверной проверочной процедуры того же модуля, без окружающей транзакции. Для наблюдения исключений ловить их только в проверочном вызывающем коде.

1. Проверить `ТранзакцияАктивна() = Ложь` до вызова. Передать новый `Массив` и `Ложь`; ожидать normal return, ровно `Шаг`, `Успех`, отсутствие новой записи ошибки этой операции и неактивную транзакцию после вызова.
2. Передать новый `Массив` и `Истина`; ожидать исключение с текстом `Учебный сбой шага`, пустой массив, запись события `onec-agent-skills.УчебнаяОперация` уровня Ошибка с описанием сбоя и неактивную транзакцию в вызывающем обработчике.
3. Повторить сбой, затем успешный вызов с отдельными новыми массивами. Ожидать те же результаты; каждый сбой создаёт отдельную запись журнала. Такой повтор безопасен в данном примере: шаг изменяет только массив, а повторная запись журнала разрешена контрактом.
4. Передать массив с единственной строкой `До` и `Истина`. Ожидать сохранение `До` и отсутствие `Успех`. Это проверяет, что исправление не очищает данные вызывающего кода.
5. Для отказа фиксации отдельно использовать воспроизводимый сбой, допустимый в конкретной учебной базе. Проверить выход исключения, отсутствие добавленного `Успех` и отсутствие оставшейся активной транзакции. Предоставленный исходник не содержит операции, способной детерминированно воспроизвести такой отказ; этот сценарий сейчас не проверен.

Проверки выполнять под исходной ролью пользователя. Если в рабочем модуле есть реальные записи данных или внешние действия, сравнить также их результаты до и после отказа. В данном исходнике записей объектов базы нет, поэтому подтверждать откат бизнес-данных по нему нельзя.

## Пределы

Статическое доказательство относится к предоставленному учебному пути. Оно не доказывает воспроизведение или устранение инцидента в рабочей базе. Нужны проверка синтаксиса установленной платформой и фактическое выполнение описанных сценариев.

Изменение массива в памяти не откатывается транзакцией. В показанной ветке `Истина` массив ещё не изменён, но при другом сбое после добавления `Шаг` эта строка сохранится даже после отката базы. Предлагаемый код гарантирует передачу ошибки, а не автоматический откат памяти или внешних эффектов. Если сама отмена транзакции породит исключение, оно может скрыть исходное; такого поведения учебный исходник не воспроизводит. Обработчик рассчитан на предоставленный контракт вызова, а не на вызов внутри чужой транзакции.
