# Результат

Предлагаю один пакет запросов: поместить исходные идентификаторы и товары во временную таблицу, левым соединением прочитать цены, затем заполнить исходную ТаблицуЗначений через соответствие по ИдентификаторСтроки. Полный предлагаемый BSL сохранён в `proposed.bsl` рядом с этим отчётом. Это предложение для проверки на целевой платформе; 1С здесь не исполнялась.

Для непустой таблицы вместо N вызовов `Запрос.Выполнить()` в цикле предлагается один вызов с пакетом из двух операторов. Для пустой таблицы в обеих версиях чтения нет; для одной строки число вызовов остаётся равным одному. Число операторов пакета, внутренних SQL-обращений и клиент-серверных вызовов — разные величины. Один вызов Выполнить не доказывает один SQL-запрос. Модуль серверный, Вызов сервера выключен: исходные N выполнений запроса нельзя называть N удалёнными вызовами общего модуля с клиента.

## Контракт и исходник

Один результат соответствует каждой исходной строке с уникальным числовым идентификатором. Сохраняются сами строки, их количество, идентификаторы, товары и порядок; Цена и ЕстьЦена полностью заменяются. Повтор A означает две самостоятельные строки результата. Для существующей записи с ценой 0 результат — `(0, Истина)`, для отсутствующей — `(0, Ложь)`.

Регистр независимый и непериодический. Полный ключ поиска — единственное измерение Товар; дополнительных параметров даты, склада, организации или вида цены нет. Ресурс Цена числовой. По условию одному товару соответствует не более одной записи. Входная таблица уже имеет заданные типы колонок, что существенно для использования ТаблицыЗначений как внешнего источника временной таблицы.

В исходнике не обнаружена ошибка результата на заданном успешном пути. Установленная причина для изменения — запрос выполняется для каждой строки, в том числе повторно для одинаковых товаров. Цель предложения — сохранить результат и уменьшить число вызовов выполнения запросов.

## Почему это сохраняет требуемый результат

Временная таблица содержит по одной записи на исходную строку: ИдентификаторСтроки и Товар. Нет РАЗЛИЧНЫЕ, группировки или удаления повторов. Для каждой такой записи соединение по полному ключу имеет либо одну правую запись, либо ни одной. Поэтому итог содержит ровно одну запись для каждого исходного идентификатора.

При найденной записи берётся её Цена и выставляется Истина, включая нулевую цену. При отсутствии левого соответствия правые поля равны NULL: ЕСТЬNULL задаёт цену 0, а проверка правого Товар ЕСТЬ NULL даёт Ложь. Пустая строка товара, если она присутствует в корректных входах, не является NULL: найденная запись с пустым товаром всё равно означает Истина. NULL обрабатывается в запросе; смешения с Неопределено или пустой ссылкой нет.

Порядок результата запроса не задан и не используется. Соответствие связывает результат с числовым идентификатором, а повторный обход исходной таблицы сохраняет её порядок и повторы. Сопоставление товаров выполняется самим запросом; BSL-соответствие по строковым товарам не вводит отдельные правила сравнения строк. Оба изменяемых поля присваиваются в каждой исходной строке, поэтому старые значения не сохраняются.

Границы аргумента: заданы уникальные идентификаторы, типизированные корректные входы, кардинальность справа не более одного, одинаковая доступность записей и неизменность цен на время операции. Между итерациями нет значимых записей, дополнительные параметры отсутствуют. Это обосновывает преобразование в принятой модели задачи, но не заменяет платформенную проверку и не является утверждением о выполненной проверке эквивалентности для всех данных и версий 1С.

При исключении чтения старая процедура могла успеть изменить первые строки; новая начинает заполнение после чтения всего результата. Это различие прямо исключено из требования. Конкурентные изменения и изменение доступности записей также исключены условием. При нескольких правых записях на товар доказательство нарушается; такую ситуацию нельзя исправлять произвольным выбором одной цены или РАЗЛИЧНЫЕ.

## Фактически выполненные проверки

Прочитаны только разрешённые постановка, данные, исходник и файлы скилла. Применены правила onec-query-review о полном ключе, кратности, повторах, отсутствии соответствий, порядке и моментах чтения. Интернет, 1С, внешние приложения и другие чаты не использовались.

Запущен сохранённый Python-скрипт `verify_model.py` стандартной библиотеки. Точная команда, фактические stdout/stderr и код завершения находятся в `checks.txt`; stderr пуст, exit code 0. Скрипт моделирует построчное чтение и левое соединение с отображением по идентификатору. Результаты соединения намеренно развёрнуты перед построением соответствия, чтобы проверить независимость заполнения от порядка выборки.

На предоставленных данных обе модели дали:

| ИдентификаторСтроки | Товар | Цена | ЕстьЦена |
|---:|:---|---:|:---|
| 1 | A | 10.00 | Истина |
| 2 | B | 20.00 | Истина |
| 3 | A | 10.00 | Истина |
| 4 | C | 0.00 | Ложь |
| 5 | Z | 0.00 | Истина |

Смоделированное число вызовов Выполнить: 5 и 1. Дополнительно прошли восемь явных случаев: пустой вход; одна найденная цена при прежнем ЕстьЦена=Ложь; одна отсутствующая цена при прежнем ЕстьЦена=Истина; одна найденная нулевая цена; все товары отсутствуют; пустой регистр; повтор товара с нулевой ценой; найденная запись с пустым товаром. Прошли 300 воспроизводимых сгенерированных случаев с seed=20261013. Всего 309 случаев, с проверкой результата по каждой строке, порядка, кратности, замены старых значений и модельного числа вызовов.

Python сравнивает строки своим точным равенством. Он не воспроизводит правила сравнения строк платформы/СУБД, числовые квалификаторы 1С, права, работу временных таблиц, синтаксис BSL или исполнение пакетного запроса. Поле модели с числом вызовов — отражение структуры алгоритма, а не инструментальное измерение 1С. Производительность модели не измерялась и ничего не доказывает о скорости решения в 1С.

## Подготовленная проверка на платформе — не выполнена

1. В отдельной тестовой базе создать указанный регистр и типизированную таблицу; зафиксировать версию платформы, режим совместимости и СУБД. Разместить процедуры в серверном общем модуле с заданными флагами. Проверить компиляцию BSL, разбор пакета, внешний источник ТаблицаЗначений, типы ЕСТЬNULL/ВЫБОР и получение последней выборки через Выполнить().Выбрать(). При недоступности средства адаптировать код и заново проверить результат.
2. Внести A=10, B=20, Z=0, отсутствие C. Подготовить две отдельные одинаковые таблицы с исходными строками; заранее поставить различающиеся старые Цена и ЕстьЦена. Выполнить исходную и предлагаемую процедуры под одной ролью без изменения данных между ними. Сверить каждую строку по позиции и идентификатору, включая товары, числовые значения и булев флаг, с таблицей выше.
3. Повторить явные граничные случаи модели. Отдельно проверить строки максимальной длины, пустую строку, кириллицу, варианты регистра и завершающие пробелы в пределах фактически допускаемых платформой ключей. Сравнивать старую и новую процедуру в одинаковой базе, а не ожидать правил Python. Несколько совпадений на один товар противоречат текущему контракту; если метаданные изменятся, сначала пересмотреть кардинальность.
4. Проверить, что пустой вход не исполняет запрос, непустой делает один вызов Выполнить, а число строк после заполнения и исходный порядок сохраняются. Использовать отладчик/счётчик вокруг вызова для числа вызовов API; технологический журнал и средства целевой СУБД — отдельно для фактических SQL-операций и плана.
5. Для замеров использовать одинаковую роль, неизменные цены, одинаковые объёмы входа и доли повторов/пропусков; зафиксировать индексы, состояние кеша, прогрев и несколько повторных прогонов обеих версий. Измерять время и потребление памяти, сопоставляя результаты по каждой строке. Проверить малые и большие объёмы. У предложения есть временная таблица и соответствие размером порядка N; при больших N оценить память и стоимость создания временных данных.

Уменьшение числа вызовов может снизить накладные расходы повторного выполнения и является ожидаемым эффектом. Фактическое ускорение, процент выигрыша, план и пригодность для максимального рабочего объёма не установлены. Если понадобится деление на пакеты ради памяти, отдельно сохранить идентификаторы и порядок и повторно проверить число чтений и контракт неизменности данных.
